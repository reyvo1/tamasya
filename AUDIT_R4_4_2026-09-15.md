# Audit dan simulasi database TAMASYA R4.4 — 15 September 2026

Paket ini menggantikan kandidat R4.3. Sebelas kelompok masalah telah diperbaiki: tujuh temuan R4.3 dan empat temuan tambahan dari simulasi nyata. Hasil ini membuktikan skenario yang tercantum, bukan jaminan seluruh cabang aplikasi bebas kesalahan atau persetujuan otomatis go-live.

## Lingkungan dan cakupan

SQL database_setup.sql bawaan diimpor ke MySQL Community 8.4.9 lokal terisolasi, port 33384, dengan PHP 8.4.24. Aplikasi dijalankan melalui HTTP PHP built-in server; uji konkurensi memakai dua proses PHP, port 38184 dan 38185. Database hotel/produksi tidak disentuh. Data, akun, kunci, dan rekening simulasi tidak disertakan dalam paket aplikasi. Tidak ada pesan Telegram atau permintaan ke layanan pembayaran eksternal.

Seluruh sumber PHP/JavaScript diperiksa sintaksnya: 102 PHP, 58 JavaScript/MJS termasuk regresi, satu skrip HTML inline; tidak ada kegagalan parsing atau referensi lokal yang hilang. Peninjauan manual berfokus pada alur bisnis dan batas transaksi yang dijelaskan di laporan R4.3. Dokumen lama di ZIP adalah riwayat, bukan instruksi pengguna ataupun bukti pengujian saat ini.

Total 104 pemeriksaan integrasi dan 55 regresi lulus. Regresi diskon juga menguji 1.000 keranjang deterministik. Pengujian meliputi setup READY, POS/void/stok, reservasi bertabrakan, retry tanpa transaksi ganda, folio, panjar, refund bank dan split, checkout, housekeeping, maintenance, dan aritmetika pajak simulasi 10%. Angka pajak adalah fixture pengujian, bukan rekomendasi tarif hotel.

Konkurensi: dua proses yang memesan periode kamar sama menghasilkan satu keberhasilan dan satu konflik; dua permintaan POS dengan operation ID sama menghasilkan satu penjualan. Uji penguncian shift membuat POS menunggu sekitar 4,2 detik sampai kunci dilepas walaupun require_open_shift_for_sale=0.

Backup dibuat oleh backup_now.php dan benar-benar diimpor ke database kedua. Semua 113 tabel dan 5 trigger pulih. Jumlah baris sama kecuali metadata backup_runs yang memang ditulis sesudah snapshot. Seluruh isi transactions, bookings, pos_products, dan journal_lines dibandingkan dan cocok; jurnal hasil restore seimbang. Backup terjadi sebelum uji kunci shift terakhir. Dump memuat akun/kunci simulasi, sehingga tidak dimasukkan dalam paket bukti publik. Log hasil dan harness disertakan untuk penelusuran.

## Batas sebelum go-live

- Jalankan smoke test pada staging dengan versi PHP/MySQL atau MariaDB, web server Apache/Nginx, HTTPS, domain, dan konfigurasi yang sama dengan produksi. PHP built-in server tidak menguji aturan .htaccess maupun pengalaman browser penuh.
- Pastikan identitas properti, domain bawaan, rekening, kategori, tarif/pajak, kredensial private, backup offsite dan password admin sesuai hotel. Jangan mengimpor data simulasi ke produksi.
- Telegram sungguhan, penyedia eksternal, perangkat printer/biometrik, offline browser penuh, dan failover lintas node belum diuji ujung ke ujung.
- Migrasi database lama bukan bagian dari pembuktian fresh install ini. Jalur legacy runRc44TaxAuditMigration mempunyai referensi helper pajak lama yang tidak tersedia pada bootstrap aktif; jangan memakai jalur legacy itu tanpa audit migrasi khusus dan backup database target.

Paket kode dapat diteruskan ke staging akhir. Go-live masih memerlukan pemeriksaan lingkungan produksi tersebut. File SQL baseline tetap skema asli tanpa transaksi atau kredensial simulasi.
