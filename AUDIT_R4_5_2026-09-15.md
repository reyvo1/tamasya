# TAMASYA R4.5 — audit transaksi manual/backfill, akuntansi dan pajak

15 September 2026. Menggantikan paket R4.4 dan R4.3. Pengujian akhir: **332 pemeriksaan integrasi/ekspor dan 64 regresi lulus**. Semua suite di bawah dijalankan pada satu rangkaian database baru. Tidak ada pengujian gagal yang dibiarkan dalam hasil akhir ini.

## Apa yang benar-benar dijalankan

Database SQL bawaan diimpor ulang ke instance MySQL Community 8.4.9 lokal terisolasi (port 33384), lalu first_install.php dan setup READY dijalankan dengan akun serta identitas hotel simulasi. Aplikasi PHP 8.4.24 menerima permintaan HTTP nyata pada 127.0.0.1. Input transaksi manual/backfill dikirim otomatis melalui API aplikasi dan hasilnya diperiksa langsung pada database. Ini bukan pengujian klik manual seluruh formulir browser, dan bukan server staging hotel pengguna.

Alur saling terkait diuji: receipt backfill → klasifikasi pajak → jurnal → alokasi kamar/extra/perpanjangan → koreksi/void → kas/bank → review periode → laporan → Night Audit dan tutup shift → backup dan restore. Uji negatif memastikan input ditolak tanpa mutasi finansial. Dua proses PHP dipakai untuk uji konkurensi.

## Bukti keterkaitan angka

- Receipt historis 105.000 pada tarif simulasi 5%: debit kas 105.000, kredit pendapatan 100.000, kredit utang PBJT 5.000.
- Receipt split 110.000 pada tarif simulasi 10%: debit kas 40.000, debit bank 70.000, kredit pendapatan 100.000, kredit utang PBJT 10.000. Rekonsiliasi bank memakai 70.000, bukan nominal bruto.
- Receipt 490.000 dialokasikan ke kamar 220.000 + extra 50.000 + perpanjangan 220.000. Hanya satu receipt kas tetap ada. Void mengembalikan folio/tanggal dan melepas hubungan tanpa menghapus uang sumber.
- Koreksi transaksi periode tertutup 105.000 → 210.000 mencatat delta tambahan 105.000. Saat dipindah bulan, delta bulan asal kembali nol dan bulan tujuan 210.000.
- Pajak dokumen 7% dipertahankan saat hanya deskripsi diedit. Pajak belum diketahui masuk akun 2199, lalu saat dokumen ditemukan jurnal berubah menjadi pendapatan dan utang pajak tanpa menggandakan penerimaan.
- Pembayaran PBJT mendebit utang pajak dan mengkredit bank, tidak menambah beban operasional. Pencairan piutang OTA menambah bank tanpa menambah pendapatan atau pajak lagi.
- Backfill tidak melekat ke shift berjalan. Transaksi live yang ditutup terkunci; Night Audit harus memeriksa semua kamar sebelum shift malam ditutup.

Tarif 0%, 5%, 7%, dan 10% adalah fixture aritmetika. Tidak ada penetapan atau verifikasi tarif pajak legal hotel pada pekerjaan ini.

## Keutuhan laporan dan backup

Semua 17 jenis laporan diuji melalui JSON; masing-masing juga diekspor CSV/XLSX/PDF (51 pemeriksaan). Identitas/checksum snapshot ekspor harus sama dengan JSON, ZIP/XML XLSX valid, CSV terbaca, dan struktur dasar PDF valid. Ini bukan pemeriksaan visual tata letak setiap halaman. Laporan payroll/inventaris dan beberapa laporan lain diuji sebagai renderer atas data fixture yang tersedia, bukan bukti seluruh workflow payroll/procurement/perangkat keras telah diuji.

Backup dibuat oleh backup_now.php sesudah rangkaian transaksi dan penutupan shift; SQL-nya benar-benar diimpor ke database kedua. Semua 113 tabel dan 5 trigger pulih. Jumlah baris cocok kecuali backup_runs yang dicatat sesudah snapshot. Isi transactions, bookings, pos_products, dan journal_lines dibandingkan penuh dan cocok; jurnal restore seimbang. Database/dump, token, kunci dan password simulasi tidak dibagikan dalam paket.

Peringatan review backfill/pajak pada fixture memang disengaja. Peringatan itu bukan error yang disembunyikan: entry unresolved atau adjustment yang belum selesai harus tetap ditandai, sementara pemeriksaan integritas akhir tidak mempunyai status FAIL. Audit perbandingan tarif kini versus snapshot lama dapat menampilkan perbedaan karena suite sengaja mengubah konfigurasi tarif; snapshot historis bukan otomatis salah dan tidak diubah massal.

## Batas klaim dan langkah produksi

Paket ini kandidat staging akhir dengan bukti yang lebih lengkap untuk jalur manual/backfill, akuntansi, dan pajak. Tidak berarti semua cabang seluruh aplikasi terbukti bebas kesalahan. Pengujian browser manual penuh, Apache/Nginx/.htaccess/HTTPS di host hotel, Telegram/provider eksternal, printer/biometrik, failover cluster, seluruh workflow payroll/procurement, serta migrasi database hotel lama belum dibuktikan ujung ke ujung.

Gunakan SQL baseline hanya untuk instalasi baru. Jangan menimpa database produksi berisi transaksi. Uji upgrade pada salinan database hotel sebelum penerapan; jalur legacy runRc44TaxAuditMigration masih membutuhkan audit migrasi khusus sebagaimana laporan R4.3/R4.4. Verifikasi identitas/domain, aturan pajak hotel, rekening, hak akses, kredensial private, password admin, dan backup offsite pada lingkungan deployment sebenarnya.

Kode, SQL baseline, dan paket hasil tidak berisi transaksi simulasi. Script harness dalam ZIP bukti merekam skenario dan perlu konfigurasi database lokal private; jangan arahkan ke database hotel hidup.
