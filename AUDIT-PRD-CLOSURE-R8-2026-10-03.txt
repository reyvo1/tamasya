ROOT CAUSE
1. mysql-canonical-authority-verify.py derived expected CREATE TABLE objects only from backtick-quoted identifiers. HQ schema uses unquoted identifiers, so expectedTables incorrectly became zero.
2. mysql-bootstrap-runtime-boundary.sh had a property-specific schema_release_state attestation block for every database profile. HQ has an independent schema and intentionally does not contain the PMS schema_release_state table. Fixing only the parser would expose this second architectural mismatch next.
